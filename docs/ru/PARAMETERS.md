# Параметры CRT Overlay

[English](../PARAMETERS.md) · **Русский**

[Руководство](../../README.ru.md) · [Архитектура](ARCHITECTURE.md)

Справочник соответствует атрибутам `Option` и проверкам в `src/CrtSettings.cs`. Значения по умолчанию относятся к `new CrtSettings()` / Balanced. Другие пресеты переопределяют часть значений. Числовые диапазоны включают обе границы, если не указано иначе.

## Синтаксис и приоритет

CLI использует отдельные аргументы: `--brightness 1.1`, а не `--brightness=1.1`. Имена параметров вводятся как указано в таблицах. Для дробных чисел CLI нужен десятичный разделитель **точка**. Строка сведения имеет вид `"0.4,0.0"`: запятая разделяет X и Y. В числовых полях редактора можно использовать точку или запятую.

Логические CLI-параметры принимают `on/off`, `true/false`, `1/0`. Параметр без значения, например `--rolling-scan`, означает `on`. В JSON используются `true/false`, числовые значения и строки соответствующих типов.

Сначала загружается пресет, затем применяются явные CLI-параметры, независимо от положения `--preset`. Если пресетов несколько, основой становится последний. Повторный обычный параметр перезаписывает предыдущий. `--curvature` задаёт обе оси, поэтому порядок относительно `--curvature-x/y` имеет значение.

JSON использует имена C#-свойств из таблиц. Регистр ключей не учитывается. Пропущенные поля получают значения по умолчанию. Неизвестные поля, `null` вместо значения и выход за диапазон вызывают ошибку. Комментарии и завершающие запятые не поддерживаются. Сохранение записывает полный объект настроек, включая параметры запуска; язык UI хранится отдельно.

`SchemaVersion` — версия JSON-пресета, без CLI-параметра. Отсутствующая версия означает 1, принимаются 1 и 2. Сохранение всегда записывает 2. Неподдерживаемая версия отвергается до разбора остальных полей с понятным сообщением. Старые пресеты сохраняют прежний путь (`TubeProfile=legacy`). Встроенные паспортные данные трубок имеют собственную схему версии 1 и не являются пользовательскими пресетами.

При загрузке JSON в редакторе или смене пресета из трея сохраняются текущие `Monitor`, `Present`, `SyncInterval`, `Fps`, `TestSeconds`, `DebugLayer`, `Cursor`. При первоначальном запуске эти параметры могут задаваться из JSON. Флаг `PerformanceLog` задаётся только в CLI, также сохраняется при смене настроек и не сериализуется в JSON.

## Сброс в редакторе

Кнопка **Сбросить** в строке основных или расширенных настроек возвращает только этот параметр к стандартному значению из таблиц ниже. Для пары координат X/Y сбрасываются обе координаты. **Вернуть пресет** восстанавливает исходные значения выбранного пресета или открытого файла.

Можно сбросить и ошибочное поле, не исправляя его вручную. Правки, незаконченный и ошибочный ввод в других строках сохраняются. Если все значения допустимы и включён **Предпросмотр на рабочем столе**, изображение обновляется. Пока в другом поле остаётся ошибка, на экране сохраняется последний корректный предпросмотр, а **Применить** и **Сохранить в файл…** недоступны. При выключенном предпросмотре на экране остаются последние применённые настройки.

Сброс не применяет настройки и не записывает файл. Нажмите **Применить**, чтобы оставить результат на текущий сеанс, или **Сохранить в файл…**, чтобы также записать его в JSON. До применения **Отменить и закрыть**, Escape и крестик возвращают последние применённые значения.

## Физический профиль трубки

Выберите в редакторе «Расширенные настройки», затем раздел «Физический профиль трубки». Эти параметры не меняют выбор консоли. Все настройки раздела, кроме выбора трубки, действуют только при активном физическом профиле.

| CLI | JSON | По умолчанию | Допустимо | Значение |
|---|---|---|---|---|
| `--tube-profile` | `TubeProfile` | `legacy` | `legacy`, `philips-a51eal155x` | Прежний путь или документированный кинескоп Philips |
| `--tube-area` | `TubeArea` | `fit` | `fit`, `stretch` | Вписать полезную область 411.2:308.9 в дисплей или явно растянуть |
| `--tube-scale` | `TubeScale` | 1 | 0.25–1 | Доля размера выбранной области относительно её максимального размера |
| `--tube-content` | `TubeContent` | `fit` | `fit`, `crop`, `stretch` | Вписать весь рабочий стол, заполнить с обрезкой или растянуть в растр трубки |
| `--view-distance-mm` | `ViewDistanceMm` | 1000 | 300–3000 | Расстояние осевого наблюдателя от центральной вершины стекла, мм |
| `--tube-white` | `TubeWhite` | `reference` | `reference`, `temperature` | Белый x=0.313, y=0.329 из условий даташита или настройка `temperature` |
| `--tube-luminance` | `TubeLuminance` | `relative` | `relative`, `reference` | Относительная яркость или дополнительный множитель 79 / `display-white-nits` |
| `--display-white-nits` | `DisplayWhiteNits` | 120 | 40–1000 | Введённая пользователем яркость белого выходного SDR-дисплея, кд/м²; только для reference |

При `tube-area=fit` на 1920×1080 область около 1438×1080 пикселей до перспективы; при `tube-scale=0.5` обе стороны уменьшаются вдвое. `tube-content` сохраняет/меняет пропорции рабочего стола относительно физического растра, без анализа игровых рамок и без предположения о квадратных пикселях исходной консоли. `tube-area=stretch` сознательно растягивает и трубку, и изображение. Геометрия не переназначает клики Windows.

Физический профиль заменяет первичные цвета `gamut`, тип и период художественной маски `mask`/`mask-scale`; их значения сохраняются для возврата в legacy. Отключить физическую маску можно через `mask-strength=0`; P4 тоже отключает её. `soft-mask`, `mask-compensation`, насыщенность, гамма, свечение, фокус, сведение и кривизна остаются художественными поправками. Для одной только проекции поверхности задайте `--curvature 0`. Контур углов оценочный, регулируется `corner-radius`.

Статус редактора напоминает, что затухание, пятно и свечение оценочные. `phosphor` и `decay-r/g/b` работают по прежним правилам, профиль Philips не назначает им статус паспортных данных. Режим reference задаёт относительный масштаб по документированной яркости при определённых условиях, а не измеряет ваш дисплей. `brightness` остаётся отдельным множителем. Трансмиссия стекла 0.41 — справочная величина; яркость 79 кд/м² уже относится к свету после стекла. Художественные эффекты, гамма и SDR-клиппинг влияют на результат.

## Геометрия, сведение и фокус

| CLI | JSON | По умолчанию | Диапазон | Значение |
|---|---|---|---|---|
| `--curvature-x` | `CurvatureX` | 0.08 | 0–0.4 | Коэффициент искривления по X |
| `--curvature-y` | `CurvatureY` | 0.08 | 0–0.4 | Коэффициент искривления по Y |
| `--corner-radius` | `CornerRadius` | 0.03 | 0–0.25 | Радиус углов в нормированных координатах изображения |
| `--overscan` | `Overscan` | 0 | 0–0.15 | Сжатие диапазона выборки относительно центра, обрезающее края |
| `--convergence-r` | `ConvergenceR` | `"0.4,0.0"` | X/Y: −10…10 | Смещение R относительно G, в пикселях вывода, усиливается к краям |
| `--convergence-b` | `ConvergenceB` | `"-0.4,0.0"` | X/Y: −10…10 | Смещение B относительно G |

`overscan = 0.1` сжимает диапазон UV на 10% суммарно, а не обрезает по 10% с каждой стороны. `curvature-x/y` — художественная аппроксимация; коэффициенты не имеют единиц миллиметров или радиуса реальной трубки. При физическом профиле она добавляется к перспективной проекции поверхности из даташита.

## Луч, сканлайны и маска

| CLI | JSON | По умолчанию | Допустимо | Значение |
|---|---|---|---|---|
| `--mask` | `Mask` | `aperture` | `none`, `aperture`, `shadow`, `slot` | Нет маски / апертурная / теневая / щелевая |
| `--mask-strength` | `MaskStrength` | 0.35 | 0–1 | Смешение изображения с маской |
| `--mask-scale` | `MaskScale` | 1 | 0.5–8 | Масштаб рисунка; горизонтальный период RGB до геометрии — примерно 3 × значение пикселей |
| `--soft-mask` | `SoftMask` | 0.65 | 0–1 | Смешение мелкой маски со средним для уменьшения муара |
| `--mask-compensation` | `MaskCompensation` | `true` | Логическое | Нормализация средней яркости маски |
| `--scanline-strength` | `ScanlineStrength` | 0.5 | 0–1 | Смешение с моделью луча |
| `--scanlines` | `Scanlines` | 540 | 180–2160, целое | Число виртуальных строк по высоте изображения |
| `--beam-min` | `BeamMin` | 0.5 | 0.2–2 | Минимальная ширина луча в модели |
| `--beam-max` | `BeamMax` | 1.4 | 0.2–3 | Максимальная ширина луча в модели |
| `--horizontal-blur` | `HorizontalBlur` | 0.35 | 0–3 | Смещение горизонтальных выборок в пикселях вывода |

Нужно `beam-min <= beam-max`. В шейдере sigma гауссиана равна `0.4 × lerp(beam-min, beam-max, sqrt(luminance))` в единицах расстояния между виртуальными строками; яркость ограничивается до 0–1. Эти параметры не являются измеренным диаметром электронного пятна. Число строк не равно горизонтальному разрешению TVL. В legacy маска формируется до геометрического преобразования и искривляется вместе с изображением. Физическая маска вычисляется в Geometry по координатам поверхности и производным конечной проекции; её период не зависит от overscan. В режиме P4 цветная маска принудительно отключается.

## Цвет, гамма и свечение

| CLI | JSON | По умолчанию | Допустимо | Значение |
|---|---|---|---|---|
| `--gamut` | `Gamut` | `SMPTE-C` | `P22`, `SMPTE-C`, `EBU` | Набор первичных координат для цветовой матрицы |
| `--temperature` | `Temperature` | 6500 | 4000–12000 | Температура белого, K, аппроксимация дневного белого |
| `--gamma` | `Gamma` | 2.4 | 1–3.5 | Художественная коррекция отклика ЭЛТ после sRGB-декодирования |
| `--output-gamma` | `OutputGamma` | 2.2 | 1–3.5 | Коррекция выходного кодирования |
| `--brightness` | `Brightness` | 1 | 0.1–3 | Множитель итоговой линейной яркости |
| `--saturation` | `Saturation` | 1 | 0–2 | 0 — яркостная составляющая, 1 — исходная насыщенность |
| `--bloom` | `Bloom` | 0.2 | 0–2 | Добавление многоуровневого свечения ярких областей |
| `--halation` | `Halation` | 0.1 | 0–1 | Добавление широкого слегка тёплого ореола |

Входной sRGB декодируется кусочной функцией. `gamma` затем применяется как степень `gamma / 2.2` к линейному сигналу. Финал использует степень `2.2 / output-gamma` перед sRGB-кодированием. Поэтому текущие регуляторы не следует трактовать как две точные паспортные степенные характеристики аппаратуры. `brightness` не измеряется в кд/м². `phosphor` и `gamut` — независимые настройки: первая управляет временной моделью/монохромностью, вторая — первичными цветами.

## Послесвечение и развёртка

| CLI | JSON | По умолчанию | Допустимо | Значение |
|---|---|---|---|---|
| `--persistence` | `Persistence` | 0.35 | 0–1 | Множитель базовых времён затухания |
| `--phosphor` | `Phosphor` | `P22` | `P22`, `P4`, `custom` | Временной профиль; P4 также монохромный |
| `--decay-r` | `DecayR` | 6 | 0.001–200 | Базовая tau красного, мс, только custom |
| `--decay-g` | `DecayG` | 4 | 0.001–200 | Базовая tau зелёного, мс, только custom |
| `--decay-b` | `DecayB` | 2 | 0.001–200 | Базовая tau синего, мс, только custom |
| `--rolling-scan` | `RollingScan` | `false` | Логическое | Импульсное возбуждение строк с интегрированием света за кадр |
| `--rolling-compensation` | `RollingCompensation` | `true` | Логическое | Компенсация средней яркости rolling |
| `--scan-hz` | `ScanHz` | 60 | 24–240 | Эмулируемая частота развёртки/полей, Гц |
| `--bfi` | `Bfi` | 0 | 0–0.9 | Целевая доля затемнённых выходных кадров |
| `--interlace` | `Interlace` | `false` | Логическое | Чередование чётных и нечётных виртуальных строк |

Для P22 базовые tau равны 6/4/2 мс, для P4 — 24 мс на канал. Это эффективные настройки текущей модели, не результаты измерения конкретного люминофора. `tau_effective = tau_base × persistence`. При стандартных P22 и persistence=0.35 получается 2.1/1.4/0.7 мс. Чтобы задать custom-времена непосредственно, используйте `persistence=1`.

Без rolling история обновляется как максимум текущего возбуждения и экспоненциально затухшей истории. `persistence=0` отключает хвост в этом режиме. В rolling остаётся численный минимум tau 0.01 мс для устойчивости FP16; хранение мгновенного состояния отделено от среднего света за кадр. Компенсация нормирует энергию импульсов, но не устраняет аппаратные ограничения дисплея.

При interlace строка возбуждается через одно поле. BFI применяется в самом конце к уже сформированному изображению и распределяется по счётчику рендеров; фазы не синхронизированы с физическим лучом или сканированием панели. Большие значения уменьшают световой поток и могут вызывать заметное мерцание.

## Журнал производительности

`--performance-log on` включает диагностику без автоматической остановки приложения. Флаг доступен только в CLI (`JsonIgnore`), по умолчанию выключен, сохраняется при изменениях из трея/редактора и не добавляет полей в схему 2. Пресеты схем 1 и 2 совместимы. Параметры запуска в редакторе не показываются.

Раз в 10 секунд `%LOCALAPPDATA%\CrtOverlay\crt.log` получает:

| Поле | Значение |
|---|---|
| `interval-s` | Реальная длительность интервала, включая возможную паузу |
| `present-fps`, `capture-fps` | Число успешных вызовов Present и новых захваченных кадров за секунду; не внутренний FPS игры |
| `render-wall-ms`, `render-wall-max-ms` | Среднее и максимальное время захвата, курсора, отправки CRT-команд и Present, включая ожидания; не чистое CPU-время и не задержка ввода |
| `gpu-effects-ms`, `gpu-max-ms`, `gpu-samples` | Среднее, максимум и число GPU-замеров CRT-проходов без захвата, подготовки курсора и Present. Выборка одного кадра из 16, четыре набора запросов; занятые наборы пропускаются |
| `cpu-process` | CPU-время всего процесса относительно прошедшего времени и числа логических процессоров; 100% означает занятость всех логических процессоров |

GPU-результаты опрашиваются с `DoNotFlush`, без ожидания готовности. Результаты с разрывом счётчика GPU отбрасываются. При отсутствии результата выводится `n/a`; ошибка запросов отключает только GPU-замеры для текущего renderer. После восстановления renderer счётчики создаются заново. Один отчёт может захватывать паузы и смену настроек: для сравнения сохраняйте одинаковые сцену, пресет, монитор и частоту. Диагностика добавляет накладные расходы и по умолчанию выключена.
